# Changelog

- 2026-10-03
  - The web page and the README link the images, `SHA256SUMS` and the attestation bundles through the bucket's HTTPS endpoint, `https://freebsd-images.s3.us-east-1.amazonaws.com/artifacts/`, instead of the HTTP website endpoint; it serves the same objects with the same size, ETag and content type. The page still reads the size, date and checksum over HTTP from its own origin because the bucket sends no CORS headers, and its note under Verify says the page and the checksum on each card are served over HTTP.
  - The download page is valid HTML5 with one card per image: a download button, the build attestation link, the size and publish date read from the bucket, and the SHA-256 with a copy button, which falls back to `execCommand` because the site is plain HTTP. A Verify section shows the `sha256sum -c` and `gh attestation verify --signer-workflow` commands, and the page gains a favicon, `theme-color` and Open Graph metadata and an unofficial, no-warranty and trademark footer. The size, date, checksum and copy buttons need JavaScript and stay hidden without it.
  - The stylesheet is rewritten around custom properties that keep the existing light and dark hex values. It drops the unused resume-template rules, the Didot font and `outline-color: transparent`, which hid the keyboard focus ring, and uses system font stacks.
  - A color changes only where the old pair failed WCAG 2.1 AA. The light-mode link `#5CB3FF` (2.00:1 on `#F5F3D7`) becomes `#2E5A80` (6.46:1) and the dark-mode visited link `#646D7E` (4.03:1 on black) becomes `#707885` (4.71:1). The hover, active and focus text (2.29:1, 3.93:1 and 2.87:1) now use existing palette colors at 5.10:1, 5.10:1 and 7.11:1, the dark-mode visited underline `#900000` (2.19:1) follows the text color, and the 3 px focus ring is `#F88017` in dark and `#000000` in light mode, both above 3:1.
  - The web uploads set `Cache-Control: no-cache` on the files they upload, so a browser revalidates `index.html` and `default.css` and shows a merged page instead of a cached copy.
  - The publish job attests the build provenance of each image with `actions/attest` v4.2.2, the maintained successor of `actions/attest-build-provenance` (now only a wrapper on it), before it uploads anything, so a failed attestation publishes nothing. Each image's Sigstore bundle is uploaded next to it as `<image>.sigstore.json` and is checked with `gh attestation verify <image> --bundle <image>.sigstore.json --repo cdf-eagles/freebsd-cloud-img`; only that job has `id-token: write` and `attestations: write`.
  - `build.sh` downloads `base.txz` and `kernel.txz` over HTTPS from `download.freebsd.org` and extracts them only after their sha256 matches the release `MANIFEST`, fetched from the same host. Before, both files came over plain HTTP from `ftp.freebsd.org` and were piped straight into `tar`; the HTTP fallback to `ftp-archive.freebsd.org` is removed because that host has no valid HTTPS certificate, so archived releases are no longer supported.
  - The image build runs on pull requests that change `scripts/build.sh` or its workflow, so a change is built before it merges, and publishes on the push to `main`, the monthly schedule and manual runs. The publish job never runs for a pull request, and publishes are serialized so two runs cannot write the bucket at the same time.
  - The publish job writes `SHA256SUMS` for both images and uploads it after them as `text/plain` with `no-cache`. The web page reads it and shows each image's checksum, and also links the file and the `sha256sum -c` command, which stay visible without JavaScript.
  - `actionlint` v1.7.12 lints the workflows in the Check YAML workflow and as a pre-commit hook.
  - Dependabot checks the pinned GitHub Actions weekly and opens one grouped `ci:` pull request, skipping releases that are less than 7 days old.
  - Every workflow has a job timeout, the lint workflows cancel superseded runs, checkouts no longer leave the token in the git config, and the pinned actions carry their version as a comment. The Shellcheck and Check YAML workflows also run when commits are pushed to an open pull request, which they missed before.
  - README: the `main` badge links to the repository, and the secrets, the bucket permissions and checksum verification are documented. The unused Git LFS rules in `.gitattributes` are removed and `.gitignore` ignores `*.swp`.
  - The S3 uploads use `aws s3 sync` from the AWS CLI on the runner instead of `parth-paradkar/upload-s3-without-acl`, which has had no release or push since 2024-09-26, runs on Node 20 and receives the AWS secret key. The bucket paths, the credentials and the `application/gzip` type of the images are unchanged, and nothing is deleted from the bucket.
  - The image build starts on a merged pull request only when `scripts/build.sh` changes. Before, any `.sh` file matched, so merging `scripts/check_cloudify.sh` rebuilt and republished both images.
  - The build VM action `vmactions/freebsd-vm` is updated from v1.5.2 to v1.5.9. The inputs the workflow uses are unchanged, and the new version is first exercised by a manual run or the monthly schedule because the image build does not run on a workflow-only pull request.
  - Pull requests and pushes that change a shell script now also syntax-check and shellcheck the `cloudify.sh` that `build.sh` generates, for a normal and a debug build (`scripts/check_cloudify.sh`, about a second). Before, only `build.sh` itself was checked, and its `cloudify.sh` heredoc was never parsed as a script.
  - The image build and web publish workflows run on a closed pull request only when it was merged. Before, a pull request closed without merging still built the images or published the web files and uploaded them to S3.
  - The RAW image is created with `truncate -s` instead of `dd` and compressed with `gzip -1` instead of `gzip -9`. On the 2026-10-03 run these two steps took about 100 s and 420 s of 1046 s.
  - The ZFS and UFS images build in parallel as a matrix, and a final job publishes both to S3 only when both succeed. Before, one job built them one after the other.
  - `ROOT_FS` in the environment now selects the root filesystem, as the usage text documents. The script read `ROOTFS` instead, so `ROOT_FS` was ignored.
  - `-d` now sets `DEBUG`, so a debug build sets the root password in the image as documented. Before, `-d` only enabled shell tracing and verbose tar output.
  - The root account is now locked in built images (`pw usermod -n root -w no`). The command was appended to `cloudify.sh` after its `exit 0` and never ran.
  - cloud-init is installed from the package matching the installed Python (`py312-cloud-init`) instead of a fixed `py311-cloud-init`, which the package repository no longer carries. Images built from 2026-07-15 to 2026-10-03 lack cloud-init, python3, qemu-guest-agent and ca_root_nss.
  - The build now fails if a package install fails or a required package is missing afterwards. Before, the build passed and uploaded the incomplete image.
  - Builds default to FreeBSD 15.1-RELEASE and the build VM is pinned to 15.1. 15.0-RELEASE reached end-of-life on 2026-09-30.
  - The build stops with an explicit error when `freebsd-update` reports an end-of-life release. Before, it ended with only `ssh exited with code 1`.
- 2026-09-28
  - The build-time pkg configuration is now removed from the image. The cleanup had misplaced quotes and never matched, so every earlier image kept the ABI pin and the plain-http repository override.
